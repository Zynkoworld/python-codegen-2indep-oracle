# zynko-oracle · `python-codegen-2indep-oracle`

**A deterministic, re-checkable decider for two-independent-implementation codegen attestations.**

An **oracle** *deterministically decides* the truth of a case — it doesn't guess, it decides. This one decides,
for a coding-task attestation, whether the task was solved by **two implementation-independent solutions that both
pass the task's own non-Claude test-suite**.

## What it proves
A single run — or N same-lab runs — is not proof. A cell is proven iff **two implementation-independent solutions
both pass** the task's own executed test-suite (the test-suite is the non-Claude judge). The oracle decides an
attestation **VALID** iff: `verdict == pass`, **and** both `arm1_pass` and `arm2_pass`, **and** `arm2` is a
genuinely different-lab LLM (`deepseek`/`mistral`/`kimi`/`glm`/`glm-flash`/`yi` — never qwen/claude/self), **and**
`arm1 != arm2`, **and** the `judge` is an executed `testsuite`.

## Proven
Measured on a **discriminating** probe corpus of **22 cases (19 VALID + 3 planted-INVALID)** — verified by
*running* the oracle, not asserted:

```
recall = 1.000    false_positives = 0    non-degenerate = yes  →  PASS
```

`verify.py` (stdlib only, no network) is the CI gate; see `.github/workflows/verify.yml`.

## Grounding (honest — medium tier)
- This is an **empirical** two-independent-implementation attestation, **stronger** than a single run or same-model
  agreement, but **weaker** than a formal proof or a byte-locked deterministic oracle. The independence comes from
  the two solutions being written by **different labs' models**; the ground truth is the task's own test-suite.
- The attestations are generated by re-executing each solution in a sealed sandbox (`unshare -rn`, no egress) against
  the task's test-suite (verify-not-relay). No solution source is shipped here — only the attestation records.
